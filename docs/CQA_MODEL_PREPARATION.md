# Gemma 4 E4B для CQA

По выбору пользователя база — `google/gemma-4-E4B-it`, Apache 2.0,
ревизия `4ecc2ba63bcac23ba4a767fc87025b1450f84c9c` (D-021).
Путь: BF16 LoRA на L40S в NVIDIA Brev → объединение с той же базой →
текстовый GGUF Q4_K_M → локальный Ollama на RTX 4060 Laptop 8 ГБ.
8 ноября выполнено реальное BF16 LoRA-обучение 40/40 шагов и создан
GGUF Q4_K_M. GGUF и LoRA скачаны, SHA256/adapter manifest проверены. Модель установлена
в Ollama как `cqa-gemma4-e4b-rubric-v1`; фактический FROM blob соответствует
SHA дообученного GGUF. Локальная проверка завершена, облачная GPU остановлена.
Прирост точности не подтверждён независимой GT-проверкой.

## Данные и формат

`tools/build_cqa_corpus.py` воспроизводит 177 собственных синтетических примеров:
по 59 на RU/KZ/EN; train 156, validation 9, holdout 12. Авторская разметка
`synthetic_author` не является независимой человеческой Ground Truth.
`reviewed=true` обозначает проверку автором и прохождение N-02, а не экспертную
оценку организаторов. Набор не содержит DEV, аудиоссылок или данных пользователей.

Есть полный исходный чек-лист, отдельные критерии, изменения N/A и шкал,
девятый критерий, поздняя идентификация, завершение/прерывание, эмпатия,
грубые ошибки и команды внутри client/bot/system. Переводы и связанные варианты
принадлежат одной части. Исходные истории и все их контрфактуалы объединены
в train/source_training_v1; отдельно написаны document_export (validation) и
currency_display (holdout). Поле scenario_family фиксирует происхождение,
scenario_group различает варианты внутри семьи. Это небольшой технический
набор с двумя контрольными семьями, не независимый benchmark качества. Изменённый чек-лист для того же диалога допустим внутри
одной части; его перенос между частями запрещён. Holdout не используется
токенизацией, Trainer, выбором параметров или подготовительным smoke.

Модель получает актуальный снимок критериев при каждом задании и возвращает
`criterion_results` как объект по текущим ID. Схема связывает применимость
с типом ответа и разрешёнными ступенями. Конвертация в прежний CriterionResult
не исправляет оценку; N-02 проверяет доказательства, затем приложение может
применить Decimal-расчёт. Это автономные инструменты подготовки: подключение
к рабочему API и сохранение карточки остаются A-21, экспорт организаторов — A-19.

Подготовка создаёт неизменяемый manifest v2 с хешами данных, prompt и формата.
SFT маскирует prompt и сохраняет родной шаблон завершения ответа. Текстовые
слои обучаются; визуальные слои заморожены. Обрезка переписки запрещена:
слишком длинный пример останавливает запуск.

Transformers5.17.0, Unsloth2026.11.3 и PEFT0.21.2.

поиск одного Q4 внутри всего нового output, проверка заголовка/ссылок,

нативный файл завершён в новом export-recovered-v1 после повторной проверки

## Воспроизведение на GPU

Перед арендой готовы исходники, авторский набор, конфигурация и hash-lock.
На сервер переносятся только отслеживаемые файлы; `.env`, `data/private/`,
ключи и данные организаторов не входят в архив. Форма создания показывала L40S 48 ГБ с диском 256 GiB за $1.77/час;
фактически в этом пилоте Brev создал 384 GiB и показал $1.79/час.
Фактическое хранение после остановки — около $0.05/час. Счётчик процесса не ограничивает
денежные расходы и не выключает VM. Сначала ограниченный пилот, затем остановка
GPU; удаление диска выполняется только после получения и проверки артефактов.

В каталоге скопированного проекта на GPU:

```bash
uv venv --python 3.12 .venv-cqa-gpu
uv pip sync --python .venv-cqa-gpu/bin/python --require-hashes tools/cqa-gpu-requirements.txt
PYTHONPATH=backend .venv-cqa-gpu/bin/python tools/run_cqa_training.py \
  --output data/private/cqa-model/gemma-gpu-v1
```

Требуется BF16-совместимая CUDA GPU; ML-зависимости не устанавливаются в обычное
backend-окружение. Lock разрешён на CPU, затем установлен и проверен на описанной L40S.
Это не гарантирует совместимость с любой другой GPU/драйвером. Профиль закреплён в `tools/cqa-training-v1.json`:
40 шагов, LoRA r=16/alpha=16, LR=2e-5, seed=42, длина 4096, batch 1,
накопление 4. Лимит обучения 1800 секунд проверяется после шага; каждый этап
имеет внешний timeout 3600 секунд. При timeout/прерывании завершается вся
группа процессов этапа, включая конвертеры/квантизаторы. Неполное обучение не допускается к экспорту.
Это ограниченный эксперимент на авторских данных, без обещания повышения качества.

Этапы идут отдельными процессами: tokenizer preflight → train → export.
`outcome.json` отмечает completed только после готового GGUF. Ошибка сохраняет
failed; повтор требует нового каталога. Экспорт читает адаптер, закреплённую
ревизию исходной базы, объединяет веса и сохраняет SHA256/Modelfile.
Проверка локальной работы и улучшения качества остаётся false до их выполнения.

После копирования каталога `export/gguf` на ноутбук:

```bash
OLLAMA_HOST=127.0.0.1:11439 ollama create cqa-gemma4-e4b-rubric-v1 -f Modelfile
PYTHONPATH=backend uv run --project backend --locked python tools/cqa_model_pack.py smoke \
  --input data/fixtures/synthetic/cqa-training-v1.jsonl \
  --model cqa-gemma4-e4b-rubric-v1 --count 6 \
  --output data/private/cqa-model/gemma-local-v1
```

Команду `ollama create` выполняют из каталога с Modelfile и GGUF; `smoke` —
из корня проекта. Smoke использует только train и проверяет формат/N-02;
его совпадения с автором не объявляются точностью на неизвестных диалогах.
Перед принятием нужна независимая разметка N-03/N-04 и сравнение исходной
Gemma с дообученным Q4 на одинаковом зафиксированном наборе.

## Установленная модель на этом ноутбуке

Имя: `cqa-gemma4-e4b-rubric-v1`, API:127.0.0.1:11439. Ollama-сервер запущен
отдельным локальным процессом; автозапуск ОС не устанавливался. После перезапуска
можно использовать сохранённый runtime и каталог моделей (на другой машине
пути заменяются своими):

```bash
CQA_OLLAMA_BIN=/home/abilkhayr/Work/Dataton/data/private/local-evaluation/runtime/bin/ollama
CQA_OLLAMA_MODELS=/home/abilkhayr/Work/Dataton/data/private/local-evaluation/models
OLLAMA_HOST=127.0.0.1:11439 OLLAMA_MODELS="$CQA_OLLAMA_MODELS" OLLAMA_NO_CLOUD=1 \
  OLLAMA_NUM_PARALLEL=1 OLLAMA_MAX_LOADED_MODELS=1 "$CQA_OLLAMA_BIN" serve
```

Секреты/кредиты Brev для локальной инференции не нужны. Проверочный CLI должен
получать текущие criteria/transcript; production-интеграция в интерфейс — A-21.

## Логи и проверки

`cqa.training`: corpus_build_*, model_pack_*, model_export_finalized,
model_smoke_case, training_job_*,
training_stage_started; внутренняя диагностика — `cqa.errors` с фиксированным
кодом. Сырые ответы допускаются только в игнорируемом приватном каталоге.
CLI подавляет вывод ML-библиотек, не печатает prompt/транскрипты/HTTP-исключения.
Сценарий отказа: изменить SHA набора в копии конфигурации → DATASET_CHANGED,
WARNING, обучение не стартует. Ошибка этапа → TRAINING_STAGE_FAILED, ERROR,
сохранённый failed. Секретные маркеры и сохранность исходников проверяются pytest.

```bash
make check
```
