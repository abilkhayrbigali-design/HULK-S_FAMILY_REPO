# Решения и история изменений плана

Дата начального плана: 2026-11-07. Это предлагаемые решения команды в рамках известных требований, а не дополнительные правила организаторов.

## D-001. Облачная модель за заменяемым интерфейсом

**Решение:** начать с OpenAI Responses API и Structured Outputs; имя модели брать из настройки. GPT-6 Astra — начальный кандидат. Провайдер подключается через внутренний интерфейс, чтобы можно было сменить модель или позднее добавить локальную.

**Причина:** за 24 часа основной ресурс направляется на точность и законченный рабочий процесс. Требование показать локальную и облачную архитектуру одновременно отсутствует.

**Проверка решения:** сравнить оценки с ручной разметкой на RU/KZ/EN, записать стоимость, задержку и ошибки. Изменить выбор, если проверка показывает преимущество другого доступного варианта. Не объявлять качество на казахском подтверждённым до этой проверки.

## D-002. React/Vite, FastAPI, SQLite

**Решение:** отдельный клиент React/TypeScript/Vite и API на FastAPI. SQLAlchemy + Alembic, SQLite и один серверный процесс. PostgreSQL — возможная последующая миграция, а не часть обязательного MVP.

**Причина:** понятное разделение работы четырёх участников и небольшая инфраструктура. Клиент собирается в HTML/CSS/JavaScript; интеграция с Dynamics 365 остаётся будущей задачей, а не обещанием готового компонента.

**Ограничение:** несколько API workers с независимыми очередями не поддерживаются этим планом. До масштабирования нужен пересмотр планировщика задач и хранения.

## D-003. AI оценивает критерии, код считает итог

**Решение:** модель возвращает применимость, ответ, объяснение и ссылки на сообщения. Сервер валидирует их и считает результат через Decimal по формуле из чек-листа. Грубые нарушения — отдельный флаг.

**Причина:** исключить случайные арифметические ошибки и обеспечить воспроизводимый пересчёт после изменения человеческого решения.

## D-004. Неизменяемые версии и история

**Решение:** оценка ссылается на конкретные версии транскрипта и чек-листа. Изменение чек-листа создаёт новую версию; повторная оценка создаёт новый запуск. Апелляция сохраняет исходный ответ и добавляет отдельное решение.

**Причина:** можно объяснить, какие правила применялись, и показать исходный и финальный результат.

## D-005. Живой роадмап

**Решение:** каждый агент обязан обновлять `docs/ROADMAP.md` при изменении статуса, зависимостей и необходимой работы. Существенная смена плана фиксируется здесь с причиной и затронутыми задачами.

**Причина:** дальнейшая работа других AI должна опираться на актуальный план, а не на неизменяемый список предположений.

## D-006. Разметка и метрики команды

**Решение:** создать ручную разметку части DEV и отдельную от настройки промптов отложенную выборку. Внутренние метрики: совпадение по критериям, ошибка итогового балла, качество N/A и флагов нарушений, с разбивкой по языкам.

**Причина:** в DEV API нет Ground Truth. Официальная формула сравнения скрытого набора неизвестна; нельзя выдавать наши метрики или самооценку модели за официальный результат.
