# Проверка работы Нурсултана перед main

Обязательная процедура по поручению пользователя (D-010), задача N-06. Нурсултан выполняет её для каждого своего PR до слияния в `main`. Для запуска reviewer не нужно ждать завершения всех N-задач: проверяется содержимое конкретного PR.

Это агент для проверки исходного кода. Выбор модели приложения CQA и настройка `OPENAI_MODEL` от этого не меняются.

## Порядок

1. Завершить относящуюся к PR реализацию, добавить проверки и обновить роадмап. Получить актуальный `origin/main`, проверить совместимость с ним и закоммитить работу в `codex/nursultan`.
2. Зафиксировать SHA базы и head проверяемой ветки. Передать отдельному reviewer полный контекст, путь к рабочей копии, эти SHA, ID задач и команды проверок.
3. Создать reviewer с **`model=gpt-6.1-sol`, `reasoning_effort=xhigh`** (Extra high). Для инструмента `collaboration.spawn_agent` при явном выборе модели использовать `fork_turns=none`, поэтому нужные сведения должны быть в самом задании.
4. Reviewer читает diff и окружающий код, проверяет контракты, логирование, расчёты, тесты и избыточность. Он не редактирует отслеживаемые файлы, не коммитит и не сливает PR.
5. Нурсултан разбирает замечания, исправляет подтверждённые дефекты и добавляет регрессии там, где они проверяют реальное поведение. Лишние зависимости/дублирование устраняются без расширения задачи.
6. Запустить относящиеся к изменениям проверки, обновить роадмап и закоммитить исправления. Reviewer повторно проверяет изменённый код и итоговый head SHA.
7. Итоговый отчёт добавить в описание PR: модель/effort, base/head SHA, просмотренная область, замечания и их решения, фактические проверки/ограничения, вывод. Размещать отчёт с SHA в PR, чтобы его запись не создавала новый коммит поверх проверенного.
8. Интегратор сверяет SHA и условия готовности, затем решает о слиянии. Отдельного отчёта AI недостаточно без нужных проверок CI/интеграции.

Любые последующие изменения кода требуют повторного просмотра нового head. Если после ревью изменён только роадмап/документация, reviewer подтверждает эти изменения и новый SHA; старый отчёт не объявляется проверкой нового коммита. При изменении main, затрагивающем зависимости PR, совместимость и соответствующая часть ревью проверяются заново.

Если среда не позволяет создать отдельного агента с указанной моделью/effort, явно зафиксировать невыполненную N-06 и передать проверку в подходящую среду. Нельзя молча подменять модель или писать, что проверка выполнена. На момент добавления этой процедуры код Нурсултана не проверен и отчёт reviewer отсутствует.

## Настройки запуска reviewer

Поля для `collaboration.spawn_agent`; в `message` нужно передать заполненное задание из следующего раздела. Это пример настройки, а не запись о запуске:

```json
{
  "task_name": "review_nursultan",
  "model": "gpt-6.1-sol",
  "reasoning_effort": "xhigh",
  "fork_turns": "none",
  "message": "Полное задание с путём, base/head SHA, задачами и командами проверок."
}
```

## Задание reviewer

```text
Ты независимый reviewer изменений Нурсултана, модель GPT-6.1 Sol, effort xhigh.
Путь к рабочей копии: [заполнить абсолютный путь].
База main: [BASE_SHA]. Проверяемый head: [HEAD_SHA]. Задачи: [ID].
Команды относящихся проверок: [заполнить из README/Makefile и новых тестов].

Прочитай AGENTS.md, docs/SCORING.md, API_CONTRACT.md, INTEGRATION.md,
LOGGING.md и CODE_REVIEW.md. Проверь diff BASE_SHA...HEAD_SHA и окружающий код.
Работай без изменения отслеживаемых файлов и без слияний/коммитов.

Проверь:
— ошибки логики и крайние случаи, Decimal, веса, N/A, секции, флаги;
— динамический чек-лист, строгие типы, полноту критериев и доказательства;
— таймауты, реальные повторы, безопасные отказы, usage и стоимость при наличии;
— наличие логов значимых операций, уровни/коды, обработку фоновых ошибок;
— отсутствие секретов, текстов диалога/промптов/ответов и дублей в логах;
— повторяющийся, недостижимый, неиспользуемый код, лишние абстракции/зависимости;
— соответствие контрактам и осмысленность тестов, сохранение старого поведения.

Для замечания укажи файл/строку, условие возникновения, последствие,
воспроизводимый пример или конкретное доказательство и рекомендуемую правку.
Отделяй подтверждённый дефект от необязательного стилистического предложения.
Запускай доступные относящиеся проверки; не заявляй прохождение непройденных.
Не выводи приватные данные, полные исключения или содержимое локального .env.

Верни: проверенные base/head SHA, область проверки, список замечаний
с важностью, выполненные проверки/ограничения и вывод о готовности к слиянию.
Если дефектов не найдено, скажи об этом явно, сохранив ограничения проверки.
```

## Условия завершения N-06

- Отдельный агент действительно запущен на `gpt-6.1-sol` / `xhigh`; параметры указаны в отчёте.
- Нет открытых подтверждённых ошибок, нарушений правил логирования или избыточности, которая вызывает проблему/нарушает принятые требования. Необязательные предложения можно отложить с объяснением.
- Нужные проверки прошли; недоступная проверка явно отмечена и её влияние оценено интегратором.
- Reviewer подтвердил финальный SHA после исправлений, а интегратор проверил совпадение с PR.
- Роадмап отражает результат. Для нового PR процедура проводится снова; прежний DONE не заменяет новую проверку.

Отчёт reviewer не является гарантией отсутствия всех ошибок. Он дополняет автоматические и интеграционные проверки.
