# Локальный пилот Qwen3.5 — 8 ноября 2026

Задача A-15: выбрать и испытать локальную модель на компьютере Абулхаира.
Предварительный кандидат — **Qwen3.5 9B Q4_K_M через Ollama**.
Это результат ограниченного пилота, а не подтверждение качества на Ground Truth.
Общий default Luna и адаптер из PR №11 этим экспериментом не изменены.

## Окружение

- RTX 4060 Laptop, 8188 MiB VRAM; Ryzen 7 7840HS; около 14 GiB доступной системе RAM.
- Ollama v0.40.15, локальная установка без системной службы и изменения драйверов.
- Сервер слушал только `127.0.0.1:11439`, облачные функции отключены.
- Одновременно загружалась одна модель, один запрос; расчёт — существующий N-02.
- Установлены `qwen3.5:4b-q4_K_M` (пакет 3.32 GB) и
  `qwen3.5:9b-q4_K_M` (пакет 6.55 GB). Размеры в десятичных GB.

Модель 9B целиком размещалась на GPU: runtime сообщил 33/33 слоя и
6 021 573 508 байт `size_vram` при контексте 16384. `nvidia-smi` показывал
6762 MiB общей занятой VRAM во время работы; это включает расходы runtime.
Пиковое потребление отдельным мониторингом не измерялось.

## Методика

Пять собственных синтетических диалогов: правильный ответ о часах работы на
RU/KZ/EN, оскорбление клиента на RU, EN с дополнительным девятым критерием и
инструкцией-провокацией в сообщении клиента. До вызова записаны 40 ожидаемых
решений; субъективная оценка управления грубым диалогом исключена из сравнений.
Промпт не содержит ожидаемых ответов. Это авторские проверки, не независимая
человеческая разметка и не отложенный набор.

Дополнительно использованы четыре DEV-транскрипта: по одному чату RU/KZ/EN и
один RU-звонок. Эталонных оценок в DEV нет: здесь проверялись только завершение,
форма ответа, типы, допустимые ступени и ссылки на существующие реплики через N-02.
Семантическая правильность доказательств этим валидатором не устанавливается.
Аудиоссылки модели не передавались; распознавание речи не запускалось.

Каждый запрос получает актуальный снимок чек-листа и транскрипта. Модель
возвращает ответы и доказательства, приложение вычисляет итог через Decimal.
Для локальной схемы использован объект с ключами критериев; перед N-02 он
преобразуется в список без исправления значений, N/A или доказательств.

## Прогоны

| Конфигурация | Валидных ответов | Совпадений с синтетическими ожиданиями | Замечания |
| --- | --- | --- | --- |
| 4B, v1: общая схема списка, `think=false`, контекст 8192 | 1/9 | 5/40 | Пустые доказательства и несовместимые applicability/answer |
| 4B, v2: типизированная схема по критериям, `think=false`, контекст 8192 | 8/9 | 28/40 | Ошибки N/A и консультации; длинный звонок обрезан по контексту |
| 4B, v3: та же схема, `think=true`, лимит генерации 4096 | 0/2 завершённых | Не сравнивались | Оба запроса исчерпали лимит на рассуждения до выдачи JSON; следующий запрос остановлен |
| 9B, v4: типизированная схема, `think=false`, контекст 16384 | 9/9 | 38/40 | Объяснение до 320 символов, до трёх доказательств на критерий |

9B: RU/KZ/EN простые примеры — по 8/8, грубый пример — 5/7,
пользовательский критерий с провокацией — 9/9. В грубом примере `needs`
вернулся как `false`, `identification` как `true` вместо ожидаемых N/A.
Флаг оскорбления определён верно. Все четыре DEV-ответа прошли N-02.

Медиана полного времени запроса 9B — **26.102 с**, диапазон 23.621–34.066 с.
Первый запрос включал загрузку модели 10.344 с; медиана остальных восьми —
25.586 с. Медиана генерации — 40.36 токена/с. Для 4B/v2 медиана валидных
ответов — 15.202 с. Это измерения одного последовательного прогона на этом GPU.

Отдельный живой smoke через штатный `create_app`, API, worker и файловую SQLite:
новый синтетический EN-диалог импортирован, создан чек-лист с девятым критерием,
один настоящий запрос к 9B дал `completed`. N-02 рассчитала и сохранила девять
критериев; `original` и `final` совпали. После остановки и нового запуска приложения
карточка полностью совпала с сохранённой, повторного AI-вызова не было.
Использовалась только временная приватная обёртка провайдера, без правок backend.

Проверены события `cqa.worker`: `evaluation_started`, `evaluation_completed` и
отсутствие текстов синтетических сообщений и маркеров провокации в захваченных
логах `cqa`. Ошибки runtime/адаптера этим успешным smoke не покрыты; это часть X-03/N-05.
Сервер после испытания остановлен; модели и runtime оставлены для повторного запуска.

Конфигурации отличаются моделью и параметрами. Таблица не изолирует влияние
размера модели от схемы и контекста. v1/v2 — предварительная диагностика;
после неё схема и бюджет уточнялись. Повторные прогоны и вариативность не измерены.

Параметры v4: `temperature=0`, `seed=42`, `num_ctx=16384`, `num_predict=3072`,
`think=false`, без автоматических повторов. Остальные параметры runtime —
поставляемые с выбранным тегом модели. Лимит генерации должен помещаться в
оставшийся контекст; 8192 оказался недостаточен для длинного звонка и ответа.

## Что осталось

Перед окончательным выбором выполнить N-03/N-04: независимая ручная разметка,
разделение настроечной и отложенной частей, метрики по языкам, N/A, нарушениям
и итоговому баллу. Два неверных N/A на грубом примере остаются известной проблемой.
Нельзя переносить долю совпадений на этих простых примерах на скрытые 10 диалогов.

Промышленное подключение локального провайдера остаётся X-03: выбор провайдера,
таймауты, ограниченные повторы, сохранение usage при ошибке, безопасные логи и
проверки отказов. Одноразовый локальный скрипт не заменяет этот адаптер или UI.
Настоящий общий сквозной сценарий A-03 и проверка Luna этим пилотом не закрываются.

## Артефакты и воспроизведение на этом компьютере

Все исходные DEV-данные, ответы, SQLite и логи оставлены в игнорируемом
`data/private/local-evaluation/`; они не предназначены для публикации.
Итоги: `format-v2/summary.json`, `qwen9b-v4/summary.json`,
`worker-smoke-summary.json`. Зафиксированный скрипт v4 находится рядом с его итогами;
на другом компьютере эти приватные файлы автоматически не появятся.

API digest 9B: `56671c2ab9385f9cfcb404638e32cd62d88e3501d44822208363c010179a3c90`.
API digest 4B: `d8b0f5e9760cd1682034f292d7ef72ec46f432149be0df7574bf2d6e92e38c04`.
SHA-256 скрипта v4: `d67b4382ea26c88ec932ddf0603b2f4648b8faccf57c3d9d93bfe0e95fdef430`.

Для повторения поднять локальный `runtime/bin/ollama serve` с `OLLAMA_HOST`,
`OLLAMA_MODELS` из этого каталога, `OLLAMA_NO_CLOUD=1`,
`OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1`.
Из корня репозитория, после подготовки backend `.venv`:

```bash
PYTHONPATH="$PWD/backend" CQA_LOCAL_MODEL=qwen3.5:9b-q4_K_M CQA_LOCAL_RUN=repeat-9b backend/.venv/bin/python data/private/local-evaluation/benchmark.py
```

Живой API/worker smoke выполнялся командой:

```bash
PYTHONPATH="$PWD/backend" backend/.venv/bin/python data/private/local-evaluation/worker_smoke.py
```

Рабочий `benchmark.py` совпадает с зафиксированной копией v4. Если он позже изменён,
перед повторением восстановить эту копию из `qwen9b-v4/benchmark.py` в родительский
каталог. Нужен локальный `dev.json` из исходного пилота. `CQA_LOCAL_RUN` задаёт новый
каталог результатов; существующие исходные результаты перезаписывать не следует.

Источники для выбранного формата и runtime:
[тег 9B Q4_K_M](https://ollama.com/library/qwen3.5:9b-q4_K_M),
[Ollama Chat API](https://docs.ollama.com/api/chat),
[Structured outputs](https://docs.ollama.com/capabilities/structured-outputs).
