# Подготовка небольшого обучения в NVIDIA Brev

Задачи A-17/A-23, 8 ноября 2026. Пользователь располагает $50 кредитов; машины пока нет.
Подготовлен **синтетический rehearsal**, а не модель с подтверждённым улучшением.
GPU-обучение, установка ML-зависимостей на GPU и перенос GGUF ещё не проверены.

По D-018 первым платным этапом планируется запуск готовой более крупной модели.
Этот документ сохраняет техническую подготовку условного LoRA-этапа A-23;
исходная A-18 заменена. Актуальный порядок — в [AI_RESOURCE_PLAN.md](AI_RESOURCE_PLAN.md).

## Что разрешено известными правилами

В предоставленном `CQA_Hackathon_Student_Guide_v3 1.pdf`, стр. 1, команда сама
выбирает модель, сервер и хранение. На стр. 4 прямо разрешены локальная модель,
бесплатный и платный API. Для платного API требуется указать модель и полную
примерную стоимость одной оценки. Дообучение отдельно не описано; прямого
запрета в прочитанных гайде и приложении нет. Это не отдельное разрешение
загружать DEV третьим лицам. Условия облачного обучения на DEV, особенно пяти
реальных звонках, нужно уточнить у организаторов.

Поэтому этот инструмент принимает только `origin=own_synthetic` и
`reviewed=true`. Нельзя просто переименовать DEV в синтетические данные.
Аудиоссылок и полей для секретов в формате нет. На проверке организаторы заменят
критерий: каждое учебное задание содержит полный актуальный чек-лист.

Приложение `CQA_Student_Guide_Appendix_Results.pdf`, стр. 1 и 3, требует два
файла результатов в Git до стоп-кода, официальный mapping ID и номера реплик
из исходного массива с 1. Это отдельная задача A-19; подготовка обучения её не реализует.

## Готовые входы и локальная проверка

`data/fixtures/synthetic/brev-rehearsal.jsonl` содержит девять собственных коротких
диалогов RU/KZ/EN с тремя пользовательскими критериями. Это проверка формата,
N/A, произвольных ID и запуска; маленький авторский набор не оценивает качество
на DEV или скрытых диалогах и не является независимой экспертной разметкой.

Из корня этой рабочей копии:

```bash
uv sync --project backend --locked
PYTHONPATH=backend uv run --project backend --locked python tools/brev_pilot.py prepare \
  --input data/fixtures/synthetic/brev-rehearsal.jsonl \
  --output data/private/brev/rehearsal-v1
uv run --project backend --locked pytest backend/tests/test_brev_pilot.py -q
```

Формат одной строки: `schema_version=1`, `origin`, `reviewed`, `case_id`,
`language`, `split=train|validation|holdout`, `criteria`, `messages` и
`criterion_results`. Полный пример — в указанной синтетической фикстуре.
Сообщения имеют `id`, `position`, `timestamp`, `speaker`, `text`.
Результаты соответствуют N-02. Все три части должны быть непустыми.

Подготовка проверяет схему, ступени/типы, применимость, полноту критериев,
доказательства и роли через существующую N-02. Это структурная проверка,
которая не устанавливает семантическую правильность объяснений.
Точные повторы диалога отклоняются даже после смены ID или чек-листа;
семантические перефразировки нужно контролировать при ручной подготовке.

Выход содержит три JSONL и SHA-256 manifest. Существующий каталог не
перезаписывается; изменение данных выявляется перед обучением. При сбое записи
может остаться неполный каталог: без manifest он не используется. Для повтора
создайте новый каталог. Все выходы допускаются только внутри `data/private/`.

## Выбор GPU и бюджета

Условный LoRA-пилот планируем в пределах **$10 из резерва** общего плана.
Это план расходов, не автоматический лимит Brev. Конкретная цена
проверяется в окне создания машины, включая диск и прочие начисления.

Для основного кандидата Qwen3.5-9B ориентир — одна L40S 48 ГБ с Linux и
окружением PyTorch/CUDA. Публичный каталог показывал пример около $1.77/час
с диском; это не гарантия ставки или доступности в аккаунте пользователя.
Вначале выполняется двухшаговый smoke на 0.8B, затем проверяется загрузка 9B
и фактическая VRAM. Не начинайте большой прогон до успешного smoke.

Используем **BF16 LoRA**, а не обучение установленного Ollama/GGUF-пакета.
Unsloth рекомендует для Qwen3.5 избегать 4-bit QLoRA из-за различий квантования.
Его опубликованные оценки VRAM не заменяют измерение нашей конфигурации.

## Команды после создания машины

Войдите в свой Brev. Откройте терминал машины через Console/SSH. Скопируйте
только архив исходного кода этой ветки, без `.env`, приватных каталогов и ключей.
После распаковки перейдите в каталог с `backend/` и `tools/`.
Команды ниже — подготовленный рецепт; реального GPU-прохождения пока нет.

```bash
python3 -m venv .venv-brev
source .venv-brev/bin/activate
python -m pip install --upgrade pip
python -m pip install -e backend unsloth 'transformers>=5,<6'
mkdir -p data/private/brev
python -m pip freeze > data/private/brev/requirements.freeze.txt

PYTHONPATH=backend python tools/brev_pilot.py prepare \
  --input data/fixtures/synthetic/brev-rehearsal.jsonl \
  --output data/private/brev/rehearsal-v1
```

Установка идёт в отдельное окружение. ML-зависимости пока не имеют проверенного
GPU lock-файла; после smoke необходимо сохранить версии/совместимость в A-23.
Сначала зафиксируйте точную ревизию публичной базовой модели (не API-ключ):

```bash
BREV_MODEL_REVISION=$(python -c 'from huggingface_hub import HfApi; print(HfApi().model_info("Qwen/Qwen3.5-0.8B").sha)')
PYTHONPATH=backend python tools/brev_pilot.py train \
  --dataset data/private/brev/rehearsal-v1 \
  --output data/private/brev/smoke-0.8b-v1 \
  --model Qwen/Qwen3.5-0.8B --revision "$BREV_MODEL_REVISION" \
  --steps 2 --max-length 2048 --max-seconds 900
```

`--max-seconds` проверяется после optimizer step; он ограничивает только
обучающий цикл с дискретностью одного шага. Он не включает загрузку модели,
компиляцию, сохранение адаптера или итоговый validation loss. Он **не отключает
облачную машину и не гарантирует денежный предел**. Заранее поставьте напоминание
и контролируйте состояние/начисления в Brev. Некоторые экземпляры нельзя
остановить; диск может тарифицироваться при остановке.

Скрипт обучает только ответ assistant, маскируя prompt в loss. Он не обрезает
длинные примеры молча: `CONTEXT_TOO_SMALL` требует изменить контекст/набор.
В loss и validation не попадают holdout-примеры. Сохраняются адаптер, tokenizer,
ревизия модели, хеш manifest, параметры и версии библиотек. `outcome.json`
различает `completed`, `time_limit`, `failed`. Validation loss не является
точностью оценок. Файлы модели не загружаются в Hub, внешние отчёты отключены.

После успешного smoke повторить с `Qwen/Qwen3.5-9B`, её собственной ревизией
и новым выходным каталогом, сначала также на двух шагах. Только после замера
памяти/времени и подготовки достаточного размеченного набора выбирать число
шагов для содержательного эксперимента. Девять rehearsal-примеров для него не подходят.

## Что проверяем после настоящего обучения

На отложенных диалогах сравнить base и adapter при одинаковых чек-листах и
параметрах. Измерить N/A, ответы по критериям, нарушения, доказательства, итог
через N-02/Decimal, RU/KZ/EN, задержку и стоимость всех вызовов. Проверить замену
критерия и инструкции внутри транскрипта. Подбор по holdout запрещён процедурой команды.

GGUF-экспорт и локальная повторная проверка остаются в A-23: установленный
Ollama Q4 не становится дообученным от наличия адаптера. При экспорте нужно
сохранить chat template, EOS и отключённый thinking, затем снова измерить
качество. В штатный провайдер ничего автоматически не подключается.

## Логи и отказы

`cqa.training`: `pilot_started`, `pilot_prepared`, `pilot_trained`,
`pilot_completed` — INFO; `pilot_rejected`, `pilot_stopped` — WARNING;
`pilot_failed` — ERROR. Внутренний сбой один раз диагностируется через
`cqa.errors`/`log_internal_error`. Сторонний ML-вывод подавляется, чтобы не
выводить входы/промпты/ответы/исключения; подробной трассировки CUDA в терминале нет.
Исходное исключение не сохраняется. Это ограничивает диагностику первого GPU-smoke.

Воспроизводимый отказ: повторить `prepare` с тем же выходом — код возврата 2,
WARNING `INVALID_PILOT_INPUT`, прежние данные сохраняются. Невалидная разметка
или `origin=organizer_dev` отклоняются до создания выходов. Локальные тесты
проверяют наличие кода/уровня и отсутствие синтетических секретных маркеров
при ошибках схемы и внутренних исключениях.
