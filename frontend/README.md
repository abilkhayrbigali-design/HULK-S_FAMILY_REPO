# CQA frontend — Артём

React + TypeScript + Vite. Текущий инкремент: R-01, R-03 и просмотр транскрипта
из R-02. AI-запуск, оценка и апелляции не реализованы в этом интерфейсе.

## Запуск

Node.js 22.12+ (проверено на 24.22.1), npm. Из `frontend/`:

```bash
npm ci
npm run dev
```

Frontend — `http://localhost:5173`, backend — `http://127.0.0.1:8000`.
Команды разработки и предпросмотра слушают только локальный интерфейс.
Vite проксирует `/api` на backend, поэтому в клиенте нет подписанного URL,
API-ключа и настроек внешнего источника. В production сервер должен отдавать
`dist/` с SPA fallback и проксировать `/api/v1`; Vite proxy действует только
при разработке. CI проверяет сборку и сценарии браузера. Полный Compose остаётся в A-04.

По умолчанию включён настоящий API. Через селектор «Источник данных» можно
явно выбрать синтетический режим; также доступны `/?mode=mock` и `/?mode=api`.
Можно запустить `VITE_DATA_MODE=mock npm run dev`. Явный выбор в текущей вкладке
имеет приоритет над этим значением. В sessionStorage сохраняется только режим,
не диалоги, формы или ответы API. Демонстрационные изменения хранятся в памяти
и сбрасываются при перезагрузке; режим всегда обозначен отдельной полосой.
Сбой настоящего API никогда не включает mock автоматически.

Синтетические примеры в `src/mock/fixtures.ts` написаны для интерфейса: RU/KZ/EN,
четыре пользовательских критерия, все роли. Аудиоссылка `example.invalid` —
намеренно нерабочий placeholder. В демо она проверяет отображение ссылки,
а не доступность записи. Никаких AI-итогов в фикстурах нет.

## Возможности

- Список с пагинацией и фильтрами языка/канала; переход в карточку.
- Импорт по группе, JSON-массиву, `{ records }` или оболочке `{ data: { records } }`.
  Локальный предел файла — 10 МБ. Полная валидация перед POST; ошибки не выводят
  содержимое файла или его имя в консоль. Повторная отправка только по действию
  пользователя, без автоматического повтора мутаций.
- Исходные сообщения, роли, timestamp без преобразования; HTTP(S)-ссылка на
  запись с `noopener noreferrer` без автоматического запроса аудио. Транскрипт
  отображается как текст, HTML/указания из переписки не исполняются.
- Выбор чек-листа и сохранённой версии в карточке. Это пока выбор для просмотра,
  а не сохранённый AI-запуск.
- Создание чек-листа, произвольные критерии, инструкция, секция, вес, binary/scale/flag,
  ступени и N/A. Старые версии неизменяемы. ID существующего критерия сохраняется;
  новый получает UUID. Название существующего чек-листа read-only: контракт не
  предусматривает переименование.
- При 409 черновик остаётся. Можно загрузить актуальные правила для сравнения,
  явно принять новый expected_version_number и затем отправить черновик либо
  подтвердить его замену актуальной версией. Повторный конфликт снова проверяется
  сервером. Переход с несохранённой формой требует подтверждения, включая клавиатуру.
  При уходе во время сохранения интерфейс предупреждает, что отправленная
  операция может завершиться на сервере; поздний ответ не возвращает пользователя
  в покинутый редактор. Таймаут применяется и к чтению тела ответа после заголовков.

## Типы и диагностика

`src/api/schema.ts` задаёт runtime-проверки и выведенные TypeScript-типы для
используемого подмножества общего контракта. Не реализованные AI/appeal-маршруты
не дублируются. Тест читает общие синтетические примеры из репозитория. Ответ
несовместимой формы — `INVALID_RESPONSE`, без подстановки данных и алиасов полей.
Схемы чек-листов отклоняют лишние поля и проверяют все обязательные поля.

Клиент делает запросы через `ApiClient`, отменяет устаревшие чтения и ограничивает
ожидание 30 секундами. UI показывает только фиксированные безопасные сообщения,
а не `error.message/details` внешнего сервера. Логи `cqa.ui` содержат исключительно
фиксированное событие, числовой статус и код из allowlist:

- INFO: `import_started/completed`, `save_started/completed`;
- WARNING: ожидаемые 4xx, `file_rejected`, `form_rejected`;
- ERROR: `load_failed`, `import_failed`, `save_failed` для окончательных сбоев,
  таймаутов, сети/5xx/невалидного ответа; `ui_failed` при сбое рендера.

Нет логов render/polling, полных Error/Response, URL, внешних ID или payload.
При недоступном API dev-прокси пишет фиксированное `api_proxy_failed`.
Границы React/Router также используют безопасный обработчик ошибок. Playwright
проверяет консоль с синтетическими секретными маркерами при 409/422/502/503,
невалидном JSON, таймауте, сетевом отказе и исключении рендера.

## Проверки

Из `frontend/`:

```bash
npm run build                 # включает TypeScript
npm run format:check
npx playwright install chromium
npm run test:e2e              # демо, HTTP-перехват и контрактные примеры
```

Браузерная проверка настоящих модулей backend на отдельной временной SQLite:

```bash
uv sync --project ../backend --locked
CQA_TEST_BACKEND=1 npm run test:e2e
```

На текущем инкременте полный запуск прошёл: **22 passed**.

Порты 5173 и 8000 должны быть свободны. `tests/backend_harness.py` запускает
штатный `create_app` с временной файловой SQLite без ключа и подписанного URL.
Сценарий проверяет импорт JSON, карточку и выбор версии, создание чек-листа,
историю после reload и безопасный отказ POST оценки с `AI_NOT_CONFIGURED`.

Скриншоты/видео/trace по умолчанию выключены, чтобы не сохранять приватные данные;
отчёты в `test-results/` игнорируются Git. Тесты используют только собственные
синтетические данные. Скриншоты для ручной проверки при необходимости сохранять
за пределами Git. Проверены desktop 1440px и mobile 390px, клавиатурный вход,
загрузка/пустое состояние/retry, ошибки, сохранность черновика и версии.

## Границы интеграции

Список использует обязательные `latest_version_id` и `latest_version_number`.
Карточка возвращает `id`, `name`, `current_version` и `versions`.
Клиент проверяет эти структуры и отклоняет старые поля. Примеры из общего
контракта используются в проверках.

N-01, UI запуска и просмотра оценок, частное аудио и реальный импорт по
подписанной ссылке остаются отдельными задачами. Сборка, форматирование и
Playwright входят в frontend job CI.
